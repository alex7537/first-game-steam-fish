# Fish Lab v0.5 设计方案：正式本地存档 + 成长饥饿循环

> 目标：鱼缸从"刷新即逝的观赏页面"变成"持续存在的、需要照料的鱼缸"。
> 两个系统一先一后：存档是成长的前提（没有持久化，成长毫无意义）。
> 建议拆成三个 PR 依次实现，每个都可独立验收。

---

## 第一部分：正式本地存档（PR 1）

### 1.1 核心原则

- **基因（gene）与状态（state）分离存储**。基因是鱼的身份，终身不变；
  状态（饥饿、成长度、年龄）随时间变化。存档格式从第一天就体现这个区分，
  成长系统落地时无需改存档结构。
- **Token / API Key 永远不进存档**。保持现状（仅页面内存）。
- **存档损坏绝不导致游戏崩溃或静默清空**。

### 1.2 存档格式

localStorage 键名：`fishlab.save`

```js
{
  "saveVersion": 1,          // 存档格式版本（独立于基因的 schemaVersion）
  "schemaVersion": 2,        // 基因版本，加载时走已有迁移管线
  "savedAt": 1789000000000,  // 时间戳，离线结算用
  "tank": [                  // 缸内的鱼：基因 + 状态
    {
      "gene": { /* 完整基因对象 */ },
      "state": { "hunger": 80, "growth": 0.35, "age": 1240 }
    }
  ],
  "codex": [ /* 图鉴基因数组，沿用现有格式 */ ],
  "stats": {                 // 累计统计（为后续成就系统预留）
    "totalHatched": 0, "totalBred": 0, "totalEvolved": 0
  }
}
```

### 1.3 保存时机

- **自动保存**：任何变更事件（孵化/放生/繁殖/演化/图鉴变化/喂食）后
  **防抖 1 秒**写入——不要每帧写，localStorage 同步写入会卡顿。
- **兜底保存**：`beforeunload` 事件时强制写一次。
- 现有的"导出/导入 JSON"保留，作为手动备份通道，导出格式即上述完整存档对象
  （不再只是图鉴数组——升级导入逻辑以兼容旧的纯数组格式）。

### 1.4 加载与容错

启动加载流程，按序处理：

1. 键不存在 → 全新开局（三条随机鱼，现状不变）。
2. JSON.parse 失败 → **把原始字符串备份到 `fishlab.save.corrupt`**，
   toast 提示"存档损坏，已备份并重新开始"，全新开局。绝不静默丢档。
3. `saveVersion` 未来不认识 → 同上处理（备份 + 提示）。
4. 基因逐条过 `migrateGeneV1toV2()` + `sanitize()`，坏基因跳过不崩。
5. QuotaExceededError（写入超限）→ toast 提示"存储空间不足，请导出备份"。

### 1.5 验收清单（PR 1）

- [ ] 养鱼 → 刷新页面 → 鱼和图鉴原样恢复
- [ ] 手动把 localStorage 里的存档改成乱码 → 刷新 → 有提示、有备份、不崩溃
- [ ] 导入 v0.3 时代的旧图鉴纯数组 JSON → 正常迁移
- [ ] 存档里搜不到任何 token 字样

## 第二部分：饥饿与喂食（PR 2）

### 2.1 新增运行时状态（每条鱼）

| 字段 | 范围 | 含义 | 初始值 |
|---|---|---|---|
| `hunger` | 0–100 | 饱食度，100=吃饱 | 80 |
| `growth` | 0–1 | 成长度（PR 3 使用） | 孵化=0，真实馆入缸=0.5 |
| `age` | 秒 | 累计存活时间 | 0 |

### 2.2 饥饿机制

- 衰减：**每 12 秒 -1**（≈20 分钟从满到空），在 tick() 里按 dt 累计。
- 行为影响（都是软惩罚，**没有死亡**——本作是治愈系养成，饿不死鱼，
  死亡机制留给未来投票决定）：
  - hunger < 30：游速 ×0.6，尾巴摆动变慢，头顶冒"饿"字气泡（每 5 秒一次）
  - hunger = 0：停止成长（growth 不再增加），鱼趴底缓慢游动
- 选中鱼的铭牌上显示饱食度条（颜色随数值绿→黄→红）。

### 2.3 喂食交互

- 工具栏新增"🍤 喂食"按钮 → 进入喂食模式（鼠标变准星）→
  点击水面任意位置投下 1 粒饲料 → 再点按钮或 Esc 退出。
- 饲料是新实体类型（`FOODS` 数组），进 tick() 统一更新：
  缓慢下沉（约 20px/s），落底 30 秒后消失，单缸同时最多 8 粒。
- **觅食行为**：hunger < 70 的鱼会锁定最近的饲料，覆盖 wander 目标向它游
  （目标速度指向饲料，速度上限 ×1.4——饿鱼冲刺）；碰到即吃：
  hunger +35，冒一颗爱心粒子，growth 结算见 PR 3。
- 多鱼抢食：先到先得，饲料被吃掉后其他鱼恢复 wander。这会自然涌现
  "一群鱼冲向食物"的画面——不需要专门写群体逻辑。

### 2.4 离线结算（存档联动）

加载存档时用 `now - savedAt` 计算离线时长，按衰减速率扣 hunger，
**但地板是 20**（离开三天回来鱼是饿的，但不是空槽——不惩罚回归玩家）。
恢复后 toast 欢迎语："你离开了 x 小时，鱼儿们饿坏了，快喂食吧"。

### 2.5 验收清单（PR 2）

- [ ] 投食后最近的饿鱼会转向、加速、吃掉饲料，hunger 上升
- [ ] 吃饱的鱼（hunger ≥ 70）对饲料无视
- [ ] 饥饿鱼明显变慢 + 冒"饿"泡
- [ ] 刷新后 hunger 保留；关页面几小时后回来 hunger 下降但 ≥ 20
- [ ] 12 条鱼 + 8 粒饲料同屏不掉帧

## 第三部分：成长与养成闭环（PR 3）

### 3.1 成长机制

- growth 0→1 的唯一来源是**吃食**：每次进食 +0.04（约 25 次喂食成年），
  hunger=0 期间进食首次额外 +0.02（雪中送炭奖励）。
- **视觉体现**：渲染尺寸 = 基因 size × (0.6 + 0.4 × growth)。
  幼鱼是成年体型的六成大，肉眼可见地"养大了"。
  注意：**gene.size 本身永不改变**——基因是天生上限，成长是达成度。
  这条原则同样约束图鉴：speciesKey 不含 growth。
- 成长阶段仅作展示：growth < 0.5 显示"幼鱼"，≥ 0.5 显示"成鱼"，
  = 1 显示"元老"（铭牌代数旁加标签）。

### 3.2 养成门槛（给喂食一个"必须做"的理由）

- **幼鱼（growth < 0.5）不能繁殖、不能衍生新物种**，操作时 toast
  "这条鱼还没长大，先喂它几顿"。
- 这样闭环就成立了：孵化 → 喂养长大 → 繁殖/演化 → 新一代 → 再喂养。
  玩家的时间投入转化为血统积累，"我的鱼缸"有了重量。

### 3.3 平衡参数表（集中放进一个 CONFIG 常量，方便调参）

```js
const CONFIG = {
  hungerDecayPerSec: 1/12,   // 饥饿衰减
  hungerEatGain: 35,          // 进食恢复
  hungerSeekBelow: 70,        // 低于此值开始觅食
  hungerSlowBelow: 30,        // 低于此值变慢
  offlineHungerFloor: 20,     // 离线结算地板
  growthPerMeal: 0.04,        // 每餐成长
  growthAdultAt: 0.5,         // 成年线
  foodSinkSpeed: 20,          // 饲料下沉 px/s
  foodMaxOnScreen: 8,
  foodLifeOnFloor: 30,        // 落底存活秒数
  babyRenderScale: 0.6,       // 幼鱼渲染比例下限
};
```

初值是我按"20 分钟一个照料周期、25 餐养成一条鱼"拍的，**必然需要试玩后调**。
调参原则：照料周期太短会变成打卡压力，太长喂食就失去存在感。

### 3.4 验收清单（PR 3）

- [ ] 新孵化的鱼明显小一圈，喂大后尺寸平滑变化
- [ ] 幼鱼繁殖/演化被拦截且提示友好
- [ ] 图鉴复育出来的鱼是幼鱼（growth=0），不继承原鱼成长
- [ ] CONFIG 改动即时生效，无需改散落各处的魔法数字

## 实现顺序与分支建议

1. `feature/save-system`（PR 1）——独立合并，先让现有内容能持久化
2. `feature/hunger-feeding`（PR 2）——依赖 PR 1 的 state 存储
3. `feature/growth-loop`（PR 3）——依赖 PR 2 的进食事件

每个 PR 合并前照旧走视觉验收。三个都合完，游戏就从"生成器"变成了
"养成游戏"，也就到了讨论 Godot 迁移的最佳时机——迁移的是一个
玩法已验证的完整循环，而不是一堆功能碎片。
